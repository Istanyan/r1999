## 1. 结论

- **A（P12.6 + GUI 状态钩子）：17 店 / 5 局 = 3.40 店/局**，平均存活 346s，1 次 0 店短局（47s）。
- **B（P12.6 + 修正动态 Boss + GUI 状态钩子）：18 店 / 5 局 = 3.60 店/局**，平均存活 334s，无 0 店局，最低 3 店。
- B 比 A 多 1 店（+0.20/局，+5.9%），存活标准差从 174.7s 降到 56.6s，短期下限更稳。
- **但这 5 局不能证明动态 Boss 修复有效**：B 的 5 局全部只触发 Boss1，`动态本体` 日志为 0，Boss2/3 一次都没进入。B 的 +0.2 店在当前样本内只能视为噪声/稳定性差异。
- 两个版本都未达到稳定 5 店目标；B 是“更稳的 3–4 店”，A 是“波动更大的 3–4 店 + 一次 0 店”。

## 3. 逐局观察

## 4. 代码差异

A 与 B 的函数骨架相同；A 3299 行，B 3426 行，B 多 127 行，文本相似度约 97.8%。

A 的改动只有 GUI 状态上报：

- `Loop` 新增 `status_cb` / `_emit_status`；
- `R1999Script` 新增 `status_cb` 并注入 Loop；
- running / shop / run 结束 / stopped 时上报状态；
- 不改变游戏决策。

B 在 A 基础上新增：

1. 本局 Boss 序号状态：
   - `_boss_fight_count`
   - `_boss_encounter_active`
   - `_boss_dynamic_bbox`
   - `_boss_last_seen_t`
   - `_boss_track_log_t`
2. `_detect_boss_body(img)`：
   - 棋盘 ROI 内深色连通域；
   - 宽/高约 3.5 格上限，面积 ≤16 格，宽高比 0.45–2.2；
   - 有上一有效框时优先跟随 2.2 格内候选；
   - 异常帧返回 `None`，沿用最近有效框。
3. `_boss_cells_from_bbox(bbox)`：
   - 外扩 8px 后映射到棋盘格；
   - 硬上限 5×5 / 25 格，超过直接返回空集，避免 104 格封路。
4. Boss 分支改为：
   - Boss1：保留 P12.6 固定棋盘中心的 3×3 禁区和环带走位；
   - Boss2/3：使用动态本体禁区，**不进入 Boss1 环带逻辑**，回到普通关默认走位；
   - Boss 战计数在 `handle_hub` 和战斗开始处复位。
5. 日志增加 `boss 战第 N 个`、`boss{N} 动态本体 bbox=... → 禁区X格`。

## 5. 关键问题

### 5.1 B 的动态 Boss 未被实测覆盖

这是本轮最重要的限制。B 的设计目标是 Boss2/3，但 5 局全部死在 Boss1，动态分支没有执行一次。因此：

- 不能根据 B 的 3.60 店判定“动态 Boss 修复有效”；
- 也不能判定“无效”；
- 只能确认：Boss1 前段没有明显退化，B 的短期下限比 A 稳。

### 5.2 Boss1 是当前主要瓶颈

B 组 5/5 局停在 Boss1；A 组 4/5 局触发 Boss，唯一未到 Boss 的局是 47s 白怪+红区短局。说明当前版本要先把 Boss1 的存活率/击杀率做上去，否则 Boss2/3 逻辑再正确也不会被使用。

### 5.3 A 的低店短局仍是红区/白怪夹击

A 的 47s/0 店局有明确的红区 47 格、白怪候选 57 个、活区接近 0；逃逸承诺反复终止、路径为空，最后强制横向移动。该问题与 P14/P15 曾试图修复的方向一致，但本轮 A 仍是 P12.6 原逻辑，没有叠加补丁。

### 5.4 样本量限制

5 局样本不足以判断 0.2 店差异的真实性。A 的 SD（店数 1.95）远大于 B（0.55），但 B 的 5 局都在 3–4 店，也可能只是这 5 局的地图/商店分布更均匀。

## 6. 改进方式与效果估计

### 优先级 1：先让 Boss2/3 真正被测试到

可选做法（按成本从低到高）：

1. **增加局数到 10–15 局**，以出现 Boss2/3 为目标；但按本轮约 30 分钟/5 局，15 局约 1.5 小时。
2. **加测试专用钩子**：在 GUI 或环境变量中允许“跳过 Boss1/从 Boss2 开始/给足初始经济”，只用于验证动态 Boss；不要把钩子带入正式版本。
3. **离线回放**：用已有的 Boss2/Boss3 死亡截图或录像，直接调用 `_detect_boss_body` / `_boss_cells_from_bbox`，验证不会出现 104 格；这是最低成本的第一步，但不能替代实机走位验证。

效果估计：先做离线回放可以确认“检测器不再产生半张棋盘禁区”；实机 5–10 局才能确认“禁区和默认走位是否真的减少 Boss2/3 死亡”。在当前没有触发的情况下，动态 Boss 的预期收益无法量化。

### 优先级 2：Boss1 存活率

B 的 5/5 局死在 Boss1，建议下一步单独统计 Boss1：

- 进入 Boss1 时的血量、商店数、金币；
- Boss1 环带走位中被红区/白怪打断的次数；
- “环带全堵 → 硬走”出现频率；
- Boss1 死亡时间分布。

如果 Boss1 进入时血量低，优先修早期清怪/红区；如果进入时血量正常但环带被红区打断，优先修 Boss1 环带与红区的优先级。这个方向比继续改 Boss2/3 更可能提高场均店数。

### 优先级 3：低店短局

A 的 47s/0 店是明确的红区+白怪夹击。可考虑：

- 红区识别面积异常时（如 47 格）不要直接作为完整硬禁区，先做连通域/边界复核；
- “活区 0”时不要连续强制横向移动，改为短轴撤退 + 等待红区刷新；
- 但不要再回到 P14/P15 式无依据叠补丁；每次只改一个分支并跑 5–10 局对照。

效果估计：如果能把 0 店短局从 1/5 降到 0/5，按 A 当前分布，场均大约 +0.6–0.8 店；但仍不能保证到 5.0。
