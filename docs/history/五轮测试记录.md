### 致命问题（本轮最大发现）

第 3 局打了 **22 分钟、20 次商店、通关（WIN，S 评价，击杀 1191，金币 20399）**，

## R2 的教训：合并测试无法归因（我的设计错误）

R2 把**红区回退**和**选卡颜色优先**两项改动一起测，结果均店 3.43→2.14 大幅下降，
但无法区分是哪一项导致。事后分析给出指向：

| 指标 | R1 | R2 | 7b 基准 |
|---|---|---|---|
| 均店 | 3.43 | 2.14 | 5.0 |
| 均存活 | 401s | 280s | 582s |
| 逃逸 n=1 占比 | 84% | **52%** | 51.7% |
| 红区闩锁复用 | 0 次 | 有（10+） | 100% |
| 金色卡购买 | 22/106 | **4/40** | 18/78 |
| 幻彩卡购买 | 0 | 2 | 4 |
| 回血占比 | 30% | 40% | 35% |

关键矛盾：**R2 的走位指标明明更接近 P13 最佳值（n=1 52% vs 51.7%），成绩却更差**，
说明红区回退不是负因（方向是对的）。而**金色卡购买量从 22 件掉到 4 件**，
指向选卡改动才是主因——`c[2]`（颜色 rank）提到首位后，白金色（rank1）与金色（rank2）
被同批比较时，反而让大量白金卡（34 件）挤占了金币，金色卡只买到 4 件。

**结论**：选卡「颜色优先」是负向改动，必须回退。红区回退保留（指标支持）。

**方法论教训**：一轮只改一个变量。R3 起严格执行。

## R4 第 4 轮修改：修复「红区近旁跳过怪检测」

### 问题

`fast_red`（玩家两格内有红区）时，代码**完全跳过模板怪检测**：

```python
if self._mob_tpls and not fast_red:   # fast_red 时整块跳过

实测 R3 中 **912/4472 帧（20%）没有任何怪物信息**，`occupied` 缺怪格，
角色盲走进怪堆掉血，是短命局（<120s）的主因之一。

### 改动

不再跳过，改为**半分辨率检测**（`fx=0.5`，阈值 0.80→0.86 抑制误检）：

_scale = 0.5 if fast_red else 1.0
search = cv2.resize(search, fx=0.5) if fast_red else search

```

省 80%，远低于一帧 320ms，完全可接受。

## R5 第 5 轮修改：逃逸不再把怪物格当硬禁区

### 数据依据

对比 R3/R4 的逃逸决策统计，发现一个此前未注意的失衡：

| 指标 | R3 | 占比 |
|---|---|---|
| 逃离红区 BFS 路径 | 710 | — |
| **逃离红区无安全路径** | **524** | **74%** |

**四分之三的逃逸尝试找不到安全路径**。原因是候选四邻里，
`if (nx, ny) in occupied: continue` 把怪物格当**绝对禁区**直接排除，
而 `occupied` 同时包含怪物格与红区记忆。红区围住角色时四邻常全被判死，
于是 `四邻全堵 → 不建承诺 → 交回常规走位`，而常规走位优先级低于逃逸，
角色就站在红区里持续掉血直到死亡。

### 改动

怪物格从「硬禁区」降级为「高代价」（risk 4），只有非怪物格全不可走时才选它：

```python
# 原：怪物格直接跳过
if (nx, ny) in occupied:
    continue
# 改：怪物格记 4 分惩罚，仍可作为候选
is_mob = (nx, ny) in occupied
cands.append(((live_risk, 4 if is_mob else 0, nd, near_risk, edge), fd, nx, ny))
```

**依据**：红区是**持续伤害**，撞怪是**一次性小额伤害**，宁可穿一格怪。

日志新增 `穿怪格` 标记便于回看。

### 顺带排除的两个假设（数据否定）

| 假设 | 数据 | 结论 |
|---|---|---|
| 怪物信息缺失导致盲走 | 短命局「稳定0占比」21–26%，长命局 50–60% | **反向**，怪多反而活得久 |
| 贴边导致死亡 | 短命局贴边 0 次，长命局 32 次 | **反向**，贴边不是死因 |
| 分类耗时是瓶颈 | `场景` 均 296ms / 中位 148ms，占单步 42% | 真实但非主因，本轮不动 |
